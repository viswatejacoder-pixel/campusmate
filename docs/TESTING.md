### Dependency advisory review

`npm ls express-mysql-session mysql2 --all` shows the direct `mysql2@3.24.6` and the separate nested `express-mysql-session@3.0.3 -> mysql2@3.10.2`. `npm view` confirms the published `express-mysql-session` release remains 3.0.3 and pins `mysql2` to `3.10.2`; the audit fix would install `express-mysql-session@2.1.8`, which is a breaking downgrade. No compatible upstream patch or verified override was available, so D-024 remains a documented acceptance: restrict database access, keep TLS/database credentials protected, monitor the advisories, and test any future session-store upgrade in isolation before adoption.

### Release architecture and blockers

Recommended free-hosting shape: one Node/Express service serves `client/dist` and `/api` behind the host's managed HTTPS reverse proxy; use a separately managed persistent MySQL 8.4-compatible service with private/network-restricted access; configure environment variables through the host secret store; use Brevo over outbound HTTPS; keep sessions in persistent MySQL; configure the exact proxy hop count and verify forwarded HTTPS/IP behavior on the chosen host.

Free-hosting compatibility must be confirmed for persistent MySQL, Node/Express, HTTPS and forwarded headers, environment-variable secrets, outbound Brevo access, persistent session storage, connection/storage quotas, and sleep/restart policies. Current blockers are authenticated Secure-cookie behavior through a real TLS-terminating proxy, public-internet exposure evidence, physical-device responsiveness, full-app accessibility evidence, and a restore drill. The exact next action is: obtain an approved staging environment, then run the proxy-specific authenticated-cookie checks and disposable restore drill before any production release.
