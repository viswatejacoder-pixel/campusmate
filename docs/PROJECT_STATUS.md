## Known issues and risks
- The database is MySQL 8.4.13 (D-021), matching the brief. Service and server version are verified, and the `campusmate` database and `campusmate_app` user exist and connect (health 200, 2026-10-29). The schema is applied and re-runs cleanly (T-020). Session-store compatibility is now verified on MySQL 8.4 (`sessions` table created with the `CREATE` grant; session write, read back, and destroy work through the store, 2026-10-29).
- `npm audit` (2026-10-29): `express-mysql-session@3.0.3` bundles its own older `mysql2` (<=3.23.0) with 2 advisories (credential downgrade to a cleartext auth plugin; compressed-protocol DoS). The app's own `mysql2` is 3.24.6 and not affected. Low risk for a local project (no compression, local DB). Decision (author, 2026-10-29, D-024): leave it, no `overrides`, documented in security.md section 3. Do **not** run `npm audit fix --force`: it would downgrade the session store.
- A shell with `NODE_ENV=production` set overrides `server/.env` (dotenv never overrides existing variables) and makes session cookies `secure`, which breaks local HTTP login (security.md section 2). It was set in the tool session used for the T-010 checks, not in the Windows User or Machine environment. Check `$env:NODE_ENV` in your own terminal before starting the server. Re-observed 2026-10-29 (resume session): the Desktop Commander tool shell still has `NODE_ENV=production`, but the server on port 3000 issues cookies without `Secure`, so it was not started from that environment.
- OQ-12: it is unknown what stack the submitted faculty proposal named (the 26 Oct deadline has passed). If it said vanilla JS, mention the move to React in the report.
- The schedule assumes about 4 focused hours per day (an assumption, not confirmed).
- Security controls in `security.md`: the auth-related ones are implemented and scripted-tested for T-030 (bcrypt cost 12, parameterized SQL in the user model, generic login error, session regeneration, HttpOnly and SameSite=Lax cookie, 10 KB body limit, safe error responses; AUTH-09's DevTools view and SEC-02's client side are still open).
